# mdview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `mdview doc.md` opens a zathura-like window that renders the Markdown, with ```mermaid fences drawn as real diagrams.

**Architecture:** egui/eframe window draws Markdown with `egui_commonmark`; a preprocessor swaps each mermaid fence for one HTML `<mermaid id="…">` line; a `render_html_fn` hook intercepts those and draws cached PNGs, spawning up to 4 worker threads that rasterize the diagram via headless Chromium `--dump-dom` → SVG → `resvg` → PNG.

**Tech Stack:** Rust 1.100, eframe 0.36 (glow), egui_commonmark 0.25, egui_extras 0.36, notify 8, blake3, resvg 0.48, image 0.25, anyhow.

**Spec:** `docs/superpowers/specs/2026-11-20-mdview-design.md`

## Global Constraints

- Must build with no sudo and no new system packages; system WebKit/GTK dev headers are unavailable.
- Crates pinned to cache-friendly versions: `eframe = "0.36"`, `egui = "0.36"`, `egui_commonmark = "0.25"`, `egui_extras = "0.36"`, `notify = "8"`, `resvg = "0.48"`, `image = "0.25"`, `blake3 = "1"`, `anyhow = "1"`.
- Chromium lookup order: `$MDVIEW_CHROMIUM`, then `chromium`, `google-chrome`, `chrome` in `PATH`, then newest `~/.cache/ms-playwright/chromium-*/chrome-linux64/chrome`.
- Cache dir: `~/.cache/mdview/`. Mermaid JS pinned at version `11.12.0`, fetched with `curl -fsSL` into that dir when absent (`$MDVIEW_MERMAID_JS` overrides the path).
- Mermaid init must set `htmlLabels: false` and an explicit `fontFamily` (`sans-serif`); render at 2× scale.
- Cache file name: `<id>-<theme>-<RENDER_VERSION>.png` and `.err`, where `RENDER_VERSION` encodes mermaid version + render config.
- Local `![](path)` images resolve relative to the document's directory.
- Content column: `min(window_width - 64, 900)` px, centered; text wraps; wide tables/code scroll horizontally inside their own block.
- One window per process; `q` or `Esc` quits; `gg` uses a 500 ms window.
- Target: Ubuntu 24.04, X11 `:0`.

## Review Focus

- Chromium missing at startup: window still opens, text renders, one banner appears, no panic.
- Diagram source containing `<`, `&`, `"`, or the literal `</pre>`: renders correctly or shows an error box; never hangs the window.
- Invalid mermaid syntax: inline error box, `.err` marker written, reload does not retry the same source forever.
- Missing file, non-UTF8 file, or a directory passed as argument: clean non-zero exit with a readable message, no panic.
- Large document (1000+ lines, 20 diagrams): scrolling responsive, theme toggle keeps text visible, cached reopen instant.

- [ ] **Step 3: Implement `src/doc.rs`**

Line scan over `md.split_inclusive('\n')` tracking an optional open fence `(fence_char, info)`. Open a fence when a trimmed line starts with ```` ``` ```` or `~~~` (3+); close on a line of the same char that is at least as long and has no info string. While a fence is open, accumulate lines; on close, if info trimmed is `mermaid`, emit `<mermaid id="{id}">\n` and insert `id → body.trim().to_string()` (body keeps trailing newline trimmed), else emit the fence verbatim. Lines outside fences get relative `![alt](path)` URIs rewritten only when path is not absolute, has no `://`, and does not start with `#` or `data:`: prefix `file://` + `doc_dir.join(path)` (no canonicalize, so missing files stay readable later). Unclosed mermaid fence at EOF: emit the collected text as ordinary fenced text (never drop content).

- [ ] **Step 3: Implement `src/mermaid.rs`**

`RENDER_VERSION = "1-mermaid11.12.0-htmlLabelsOff-2x"`; `find_chromium` implements the Global Constraints order (env path must exist; playwright glob done by reading `~/.cache/ms-playwright/` dir entries starting with `chromium-`, sorting descending, joining `chrome-linux64/chrome`). `Renderer::new` uses `$MDVIEW_MERMAID_JS` or `~/.cache/mdview/mermaid.min.js`, creating `cache_dir`; `ensure_mermaid_js` runs `curl -fsSL -o <js> https://cdn.jsdelivr.net/npm/mermaid@11.12.0/dist/mermaid.min.js` once (spawned on first render, not in `new`, so startup never blocks).

`render`: write `<cache>/<id>-<theme>-<RENDER_VERSION>.html` containing:

```html
<!doctype html><meta charset="utf-8"><body style="margin:0"><div id="out"></div>
<script src="mermaid.min.js"></script>
<script>
mermaid.initialize({startOnLoad:false, htmlLabels:false, theme:"dark", fontFamily:"sans-serif",
  flowchart:{htmlLabels:false}, securityLevel:"loose"});
mermaid.render("d", document.getElementById("src").textContent)
  .then(r => { document.getElementById("out").innerHTML = r.svg; })
  .catch(e => { document.getElementById("out").textContent = "ERR:" + e.message; });
</script>
```

with the diagram source in `<pre id="src" hidden>ESCAPED</pre>` (escape `&`, `<`, `>`), theme substituted (`light`/`dark`). Run `chromium --headless --no-sandbox --disable-gpu --dump-dom --virtual-time-budget=5000 file://<html>`; on non-zero exit or `ERR:` in stdout write `.err` and return `Err`. Else slice stdout from first `<svg` through last `</svg>`, rasterize with `usvg::Tree::from_str` (options with `fontdb_mut().load_system_fonts()`), `resvg::render` at `Transform::from_scale(2.0, 2.0)` on a transparent pixmap, encode PNG (RGBA8), write atomically via `tmp` + rename, return path.

`html_fn` is a `static` wrapper type that, on `parse_placeholder` hit, locks the shared `Rc<RefCell<DiagramUi>>` (created in `App::new`, cloned into the closure via `Rc`) and calls `show`. `DiagramUi::show`:

1. `renderer.cached(id, theme)` → `Some(Ok(png))` → load texture once into `HashMap<String, (TextureHandle, [usize;2])>` keyed by `(id, theme)`, draw with `ui.add(egui::Image::new(&tex).fit_to_width(col * zoom))`.
2. `Some(Err(msg))` → draw a red framed label `diagram error: <msg>` with a `ui.code(source)` under it.
3. `None` and id not in `inflight` → push `(id, source, theme)` to a channel, increment `inflight`, spawn worker if `active_workers < 4`.
4. `None` and inflight → draw a 640×320×zoom placeholder frame labelled "rendering diagram…".

`poll` drains the result channel, removes from `inflight`, drops `active_workers`, inserts the error into the error map on failure, and calls `ctx.request_repaint()`.

- [ ] **Step 5: Wire actions and watcher**
